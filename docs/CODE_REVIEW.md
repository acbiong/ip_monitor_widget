## 6. USB/虚拟网卡公网查询修正（2026-09-18）

- 原实现将绑定查询和 1.5 秒默认出口兜底串联在同一个子进程内；绑定 DNS/连接耗时可能挤占预算或触发看门狗，连带失去本可成功的兜底。多个虚拟网卡还会重复请求同一默认出口，瞬时失败需等 60 秒周期刷新。
- 默认出口改为独立、优先排队的共享任务，使用 3.5 秒协作预算；绑定任务超时、非法响应或崩溃后仍可取得 fallback。保留四进程上限、每任务 6 秒看门狗、旧代次隔离及快速退出。
- 仍有 failed 结果时，间隔 3 秒最多额外重试两轮，并轮换首选服务；不重查已经得到 ok/fallback 的网卡。网络变化/退出同时取消待执行重试，绝不将默认出口冒充某个网卡已确认的公网地址。
- `/tmp/check_public_ip_recovery.py` 的 23 项隔离回归通过；包括三个指定网卡绑定阻塞、共享默认出口、默认出口晚到/瞬态失败、USB 恢复、非法/私网/过量输出、热插拔、重试限额、并发和退出。原 26 项回归按新协议调整断言后通过，22 项布局检查通过，共 71 项。
- 授权只读真实网络复测中首轮确实发生查询失败；第一轮自动重试后约 13.07 秒恢复：`wlp0s20f3=ok`，`vmnet1/vmnet8=fallback`；结束时活跃子进程为 0。未记录实际公网 IP，也未改网络配置。
- 复测时 `enx6c1ff71d8ab6` 链路为 UP，但没有 IPv4/IPv6 地址，故按原规则隐藏。该硬件获得有效地址后的真实独立出口尚无法验证；相应失败/恢复行为已用模拟子进程覆盖。

## 7. 无公网有线接入后的多出口修正（2026-09-18）

- 上一版只隔离查询进程，仍只绑定源 IP，并只以系统默认出口兜底。如果默认路由指向无外网的有线连接，增加重试并不能选择可用无线设备，虚拟网卡也会连带失败。
- Linux HTTPS 查询增加 `SO_BINDTODEVICE`，保留源地址绑定和 TLS 验证。新增独立 `interface_dns.py`：同设备/源地址 UDP 查询系统 DNS，防止 HTTPS 已绑定无线但 DNS 仍走有线。配置仅有回环解析器或无同地址族外部 DNS 时保留系统解析；未修改系统网络、路由或 DNS 配置。
- 默认出口失败后复用当前代次中其他网卡的成功结果，通过 `source_interface` 明确说明实际来源。等其余网卡完成再判定全部失败；默认查询恢复、本网卡恢复或来源拔出时更新/清除借用结果。不将无线 IP 伪装成 USB 或 VMware 的独立公网 IP。
- 新增运行依赖 `dnspython>=2.2`（本机已安装），模块总数由 12 增为 13。临时回归：设备与 DNS/TLS 契约 15 项、多出口调度 29 项、原功能 26 项、含长来源说明的布局 24 项，共 94 项通过；Python 语法检查通过。
- 授权的本机普通用户验证设备绑定成功，真实无线 HTTPS/DNS 查询成功；正常快照约 2.87 秒得到无线 ok、vmnet1/vmnet8 fallback，退出无遗留查询进程。
- 另用测试进程注入默认出口失败，并为当前无地址的 USB 设备提供文档保留源地址模拟直连失败；无线和虚拟网卡仍真实联网查询。约 2.93 秒内 USB/vmnet1/vmnet8 均得到 fallback，来源为 `wlp0s20f3`，无线为 ok；退出活跃进程数为 0。此测试没有更改系统路由，不能当作真实有线 DHCP 激活场景的实测。
